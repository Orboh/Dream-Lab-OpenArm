## Done in this step (tests first, red then green)
- `driver/openarm_zones.py`: zones schema (`reach`, `keep_out` boxes/capsules, `captured_at`), geometry (signed box distance, capsule, reach), numpy forward kinematics of Dream's
  OpenArm v2 model (points: elbow, wrist pitch, wrist, forearm, hand, tcp). Cross-checked against Dream's own `ArmModel.tool` on 50 random poses: tool positions agree to 1.5e-7 m.
- `driver/openarm_guard.py`: refuses a target whose link spheres (4 cm + 2 cm) or grasp point enter a keep-out zone; refuses everything with no zones file or zones older than
  24 h (`OPENARM_ZONES_MAX_AGE_H`); off with `OPENARM_ZONES_REQUIRED=0`. Used by `Arm.write` only (the ready/park path moves are exempt).
- `driver/openarm_lock.py` + `driver/arms.py`: `python arms.py right|left|both|status`; the driver reads the lock file on every write; a locked arm keeps holding the pose it had when it was locked.
  An unreadable lock file means no arm moves.
- `driver/conftest.py` turns guard and lock off by default in tests. 56 tests pass (fake bus, no hardware).
- Design changes versus the plan: (1) the guard does NOT enforce the painted area (Dream already clips to `reach`; the station's Home/Stop moves cross it); (2) `region` is not written to
  station.yaml: rest and ready poses have the hand below the table-top height, so a region floor at the table would drag the hand up at the start of a run. The table is a keep-out slab instead.
- Not on the real arms yet: nothing here has moved or been tested on hardware. Next: capture / build / apply / verify tool, then the viewer.
