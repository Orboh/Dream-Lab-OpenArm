# Log 003 — Driver step of the DreamLab setup: what the driver must be (2026-10-23)

## Goal
The setup page reached "Driver" (a Python class that reads and moves one arm). Find out what it must
implement and how it fits this robot, before writing anything. Nothing was written or run on the arms.

## Findings
- Interface: `robots/driver_template.py` in the Dream venv
  (`.venv/lib/python3.12/site-packages/robots/`). A driver subclasses `robots.followers.Driver` and drives ONE arm:
  - `__init__(cfg, side)`: open the bus; leave the arm powered and holding where it is.
    `cfg.can_channel` is the device, `cfg.home` lists the joints (7 for OpenArm).
  - `read()` -> `followers.Reading(positions_rad[7], velocities_rad_s[7], gripper 0..1)`.
  - `write(positions_rad, gripper)`: one target per tick; the loop checks and rate-caps it.
  - `close()` must never move the arm; `torque_off()` releases it (park first if it would fall).
  - Optional: `disengage()` (go limp for the wizard), `gripper_deg()` (lets setup record gripper
    closed/open angles), `drops_when_limp`.
- Units: joints in radians, with the URDF's zero and direction; gripper 0 closed .. 1 open.
- First safe test from the template: `dreamcli robot run --config <file> --task "..." --dry-run`
  reads the arms and logs joints without writing a target.
- The template warns that vendor LeRobot `connect()` / `disconnect()` may home or move the arm. This
  repo's bridge does exactly that on `--real` (startup alignment moves both arms), so it cannot be reused as is.
- Dream also ships `robots/damiao.py` (Damiao MIT-mode bus, ported from LeRobot), written for the
  MakerMods Metal arm's motor types, not OpenArm's.
- `openarm_can` (apt) is installed for the system python3; the Dream venv is Python 3.12, so it cannot import it.
- Correction to the earlier link advice: Dream's arm file wants `flange` = the link the gripper hangs
  off (`openarm_left_link7`) and `tcp` as an xyz offset in the flange frame (about [0, 0, 0.18] from the
  URDF: 0.1001 hand + 0.08 tcp). Setup then has the operator confirm the tool point on the real gripper
  (`dreamcli tcp`).
- Dream's arm file takes ONE arm's URDF, run in each side's own base frame. The URDF made in log-001 is
  bimanual (left/right are mirrored), so a single-arm one (`bimanual:=false`) may be the cleaner input.

## Options for the driver (not decided)
A. Thin client of the existing ZMQ bridge, one side per driver. Needs a bridge mode that connects

B. Direct Damiao over SocketCAN from the venv (python-can), using OpenArm's motor table and gains.
C. `openarm_can` bindings in a helper process.
