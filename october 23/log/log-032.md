# Log 032 — Gate 2: a grasp no longer ends the run (gripper stall alarm replaced by a lighter hold) (2026-10-27, ~12:25)

## Why
Both reviews of the goal (elephant and goldfish, 2026-10-27) rated this a blocker. log-028 had already listed it as priority 1 (finding 1, run 2).
- When the gripper closes on an object, its target leads its measured angle. After 2 s the driver let go of the object (target set to the measured angle) and set `_alarms["gripper"]`.
- That alarm was **never cleared**: only `fault` and `heat` were ever popped. `alarm()` reports it, and Dream parks the arm and ends the run.
- So **every grasp ended about 2 s after the fingers closed on the object**. In log-028 run 2 it fired even without a grasp (right after the Home move).
goal.md Gate 2 asks for exactly this: "contact does not become a fatal alarm; real faults stop safely".

## What changed (`driver/openarm_v2.py`, tests first)
- A stall (the gripper leads its measured angle by more than 4 deg for 2 s, unchanged) now starts a **hold**:
  - the gripper keeps squeezing in the same direction, with the lead capped at **`GRIPPER_HOLD_LEAD_DEG` = 4 deg** instead of the squeeze limit `motion.GRIPPER_LEAD_DEG` = 8 deg;
  - **no alarm**;
  - **one** warning in the log per hold ("gripper holds an object ... lighter grip").
- Why 4 deg: it halves the squeeze torque and coil current. The squeeze limit exists because of the 2026-09-21 coil over-temperature (README).
- **The hold ends** when Dream tells the gripper to move the other way (open), or the lead falls to 4 deg or less (the object is gone, or the target is reached). The full 8 deg lead then applies again.
- **Unchanged:** the heat stop. A gripper motor at 70 C makes the arm hold and `alarm()` ends the run. Faults and a dead control thread still end the run too.
- Code: `_send_setpoint` uses the hold lead for the gripper while `_grip_hold` is set; `_monitor` starts and ends the hold; the `alarm()` docstring and the workspace README now describe the new behaviour.

## Tests (`driver/test_openarm_smooth.py`)
The old test `test_a_gripper_that_squeezes_against_something_is_relaxed_and_reported` asserted the old behaviour. It is replaced by three tests:
1. Holding an object for 4 s: no alarm, never more than 8 deg lead, then exactly 4 deg (still gripping), one warning.
2. After a hold, Dream opens the gripper (one target per chunk, as Dream sends them): the gripper opens with the full 8 deg lead, no alarm.
3. A gripper at 70 C during a hold still ends the run with a heat alarm.

Red first (the old code raised the sticky alarm), then green. Driver suite: **127 passed**. The 1 failure is `test_blank_camera.py::test_dreams_camera_reader_loads_it_from_a_station_entry_and_delivers_black_frames`, failing since log-030.
