# Log 001 — Generate the OpenArm bimanual URDF (2026-10-23)

## Goal
Get the URDF of the robot connected to this PC (OpenArm v1.0, bimanual) so it can be used with the
Dream-1 / DreamLab setup. Procedure source: https://docs.openarm.dev/1.0/software/description/

## Findings
- The robot does not store its own URDF. The URDF comes from `enactic/openarm_description`,
  rendered with xacro using the arguments that match the hardware.
- The v1.0 docs page says it is no longer actively maintained and points to 2.0 as the latest.
  The existing setup here (`openarm-orboh`) uses v10 arms, so v10 was used.
- This PC already has ROS 2 Humble and xacro 2.1.1 (`/opt/ros/humble/bin/xacro`).
- Checkout used: `~/projects/openarm-orboh/openarm_description`
  (commit e1e52ce, 2026-04-29, remote https://github.com/enactic/openarm_description.git).
- `~/openarm_ros2_ws/src/openarm_description` is a dangling symlink (target moved to
  `Desktop/.OpenArm.superseded-by-openarm-orboh`), and its May install is an older build. Not used.
- First xacro run failed: `package 'openarm_description' not found` (xacro resolves
  `$(find openarm_description)` through the ament index). Fixed with a throwaway ament prefix in the
  scratchpad (`.../scratchpad/ament_prefix`) whose `share/openarm_description` links to the checkout.
  No colcon build and no change to the checkout.

## Step by step (how it was done)
1. Read the docs page (docs.openarm.dev/1.0/software/description/). It says: clone
   `enactic/openarm_description`, then run `xacro .../urdf/robot/v10.urdf.xacro` with
   `arm_type:=v10 bimanual:=true` and redirect the output to a `.urdf` file.
2. Searched this machine first instead of cloning: found ROS 2 Humble, xacro 2.1.1, and
   `~/projects/openarm-orboh/openarm_description` (commit e1e52ce, 2026-04-29).
3. Checked `~/openarm_ros2_ws`: its `src/openarm_description` symlink is dangling and the install is an
   old May build, so neither was used.
4. Created `october 23/urdf` and `october 23/log`.
5. Ran xacro directly: it failed with `package 'openarm_description' not found` and wrote an empty file.
6. Made a throwaway ament prefix in the scratchpad (a marker file in
   `share/ament_index/resource_index/packages/` and a symlink `share/openarm_description` to the
   checkout) and put it on `AMENT_PREFIX_PATH`.
7. Re-ran xacro (command below): exit code 0, 649-line URDF.
8. Parsed the XML with Python to confirm it is well formed: 26 links, 25 joints, 18 movable joints.
9. Compared with the Oct 19 URDF in `openarm-orboh`; it differs, so that file was left alone.
10. Wrote this log. See log-002.md for the zip step.

## Command run
```
source /opt/ros/humble/setup.bash
export AMENT_PREFIX_PATH=<scratch ament_prefix>:$AMENT_PREFIX_PATH
xacro ~/projects/openarm-orboh/openarm_description/urdf/robot/v10.urdf.xacro \
  arm_type:=v10 bimanual:=true > "october 23/urdf/openarm_bimanual.urdf"
```
Exit code 0, no warnings.

## Result
- File: `october 23/urdf/openarm_bimanual.urdf` (649 lines, robot name `openarm`).
- 26 links, 25 joints. Movable: left and right joint1-7, plus 2 finger joints per hand (18 total).
- Mesh URIs are `package://openarm_description/...`, so a consumer needs that package on its path
  (or the URIs rewritten to absolute paths).
- Differs from the older `openarm-orboh/urdf/openarm_v10_bimanual.urdf` (Oct 19, generated from an
  older description layout); the existing file was left untouched.

## Not done / open
- Structure was checked by parsing the XML only. Not loaded in a viewer, MuJoCo or Dream.
- CAN buses (`can_lead_*`, `can_fol_*`) are DOWN; the robot was not queried or moved.
- Not generated: `ros2_control` variant (needs the CAN names `can_fol_l` / `can_fol_r` passed as
  `left_can_interface` / `right_can_interface`), single-arm and no-end-effector variants.
- Open question for the user: should the URDF come from the 2.0 description instead?
