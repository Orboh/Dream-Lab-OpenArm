## 2. Our registered body `koutaueda/openarm2-faas` (created 2026-10-23)
It is Dream's FaaS layout for OpenArm v2 (`dream_ik.specs` `openarm2_faas`), not our 16-value LeRobot layout:
- **state, 36 values:**

  | Part | Span |
  |---|---|
  | `right_arm` | 0–7 |
  | `right_gripper` | 7 |
  | `left_arm` | 8–15 |
  | `left_gripper` | 15 |
  | `right_eef_xyz` | 16–19 |
  | `right_eef_rot6` | 19–25 |
  | `right_grip` | 25 |
  | `left_eef_xyz` | 26–29 |
  | `left_eef_rot6` | 29–35 |
  | `left_grip` | 35 |
- **action, 34 values:**

  | Part | Span |
  |---|---|
  | `right_eef_xyz` | 0–3 |
  | `right_eef_rot6` | 3–9 |
  | `right_grip` | 9 |
  | `left_eef_xyz` | 10–13 |
  | `left_eef_rot6` | 13–19 |
  | `left_grip` | 19 |
  | `left_arm` | 20–27 |
  | `right_arm` | 27–34 |

  The action carries `_eef_rot6`, so the job **must use `use_eef`**.
- **Units** (`_faas_side`, `client_ik._Wire`):
  - `_arm`: the URDF joints `openarm_<side>_joint1..7` in **radians**, the robot's own joints, no sign changes.
  - `_gripper`: the jaw drive, 0 closed to +0.785 (left) or -0.785 (right).
  - `_grip`: 0 closed to 1 open.
  - `_eef_xyz`: the tool point 15.9 cm past `openarm_<side>_ee_base_link`, metres, in that arm's base frame.
  - `_eef_rot6`: the first two columns of the rotation matrix.

  Dream warns: "A pose recorded another way passes every check and trains a mismatched model".
- **video:** `head` → `observation.images.head_left` (the head camera), `wrist_l` → `observation.images.wrist_left`, `wrist_r` → `observation.images.wrist_right`.

## 4. The gaps, and what closes each
1. **v3.0 → v2.1:** split the parquet and the MP4s per episode, and write `episodes.jsonl` and `tasks.jsonl`. No such converter is installed (LeRobot 0.5.2 only converts v2.1 → v3.0). We need to write it.
2. **16 values in degrees → 36 and 34 values in Dream's units:**
   - Joints: our logical degrees → Dream's model radians with the driver's own mapping (`openarm_mapping`, official: `sign * radians(deg) + zero`, the same as `OpenArm.read()`).
   - Grippers: `_grip` = (deg - closed) / (open - closed), with the driver's ends (fallback 0 / -65 deg). The drive `_gripper` = `_grip` * ±0.785.
   - Hand poses: forward kinematics with `dream_ik`'s own arm model and tool point, the code Dream uses at run time, so the poses are in the training frame.
   - The **action** is converted the same way from the leader's command.
3. **Camera key:** `chest` → `head_left`.
4. **Image shape:** the recordings are 640x480 (4:3), the station sends 1280x720 (16:9). How Dream resizes (crop or stretch) is **not checked**. Safer: record at the station's size.
5. **The head camera moved today** (log-045), so the old 10 episodes do not show today's view.
6. **Not checked yet:** whether `lerobot-record`'s degrees are exactly the driver's logical degrees. Both use `follower_<side>.json`'s `homing_offset`, but this needs one test: hold a pose, then compare one teleop frame with `OpenArm.read()`.

## 5. Recording plan (proposal, needs the user's decisions in §6)
**Before recording (once):**
1. Fix the head camera for good: looking down at the table, both grippers and the object visible. Do not move it again: the Live View must see the same view.
2. Set the recorder to the station's camera settings (`CAMERA_W=1280 CAMERA_H=720`; `FPS=30`, or 15 like the station) and name the head camera so it converts to `head_left`.
3. Start pose: the station's home (the Live View's start point), with the right J5 away from Dream's limit (log-031, log-043).
4. Calibration check (§4.6), and a conversion test on 2 episodes: `validate_dataset` must pass and the poses must match `client_ik`'s FK at the live home to under 1 mm.

**Recording:**
- One task, one prompt, word for word the one used in the Live View, for example "pick up the bottle with the right gripper".
- The right arm only, the left at rest (as in the Live View today).
- The object's place varied a little (±5 cm) around one marked spot; the same lighting.
- Each episode: from home, grasp, lift, then hold still about 1 s. 10 to 30 s each (minimum 1.6 s).
- Discard failed episodes (re-record them; do not keep them).
- The operator's teleop motions are slow and smooth: Dream learns the speed it is shown.

**After recording:**
1. Convert (§4).
2. `validate_dataset`.
3. `upload_dataset` to `koutaueda/openarm2-faas`.
4. Wait for `processed`.
5. Run `fine_tuning.create(..., use_eef=True, lr_schedule="cosine")`.
6. Choose the checkpoint in the Live View.
7. Test with the same prompt, the guard on, the user at the e-stop.
