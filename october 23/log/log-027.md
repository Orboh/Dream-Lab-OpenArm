# Log 027 — Driver review against Dream's docs and station code (2026-10-24)

## Goal
Decide what `openarm_v2.py` must provide for the predefined station, what Dream's loop and station do themselves, whether our changes really act inside the station, and what motor data Dream's API consumes.
Read-only: Dream docs (driver template, examples, control loop, safety) and installed `robots/` code (`followers.py`, `control.py`, `config.py`, `station.py`, `gripper_force.py`, `motor_arm.py`, `damiao.py`). No hardware touched, no driver change. New test: `driver/test_followerarm.py` (5 tests; driver suite 119 passed).

## What Dream's loop and station do themselves
- Each tick (`control.py`): read both arms, call `arm.alarm()` on each and raise `SafetyStop` on any text; hold on a stale camera frame (`stale_after_s` 0.2); ramp from the measured pose (`ramp_s`); gripper force cap; clamp (EE speed, `max_gripper_step` 0.05 per tick); then write.
- Station (`station.py`): asks every live arm for `alarm()`, parks alarmed arms with `torque_off`, reports dead arms (`is_alive()` False) and offers a Reset; Reset reopens arms with `close_for_reopen()` (our `drops_when_limp = True`, so it goes through `torque_off()` while alive).
- `FollowerArm` validates every write (finite, gripper in [0, 1]) and refuses read/write after `close()`/`torque_off()`.

## Motor data Dream's API takes
| Field | Where it goes | Our driver |
|---|---|---|
| `motor_temps_c` (hottest sensor per motor) | logged per inference (`~/robots-inference.jsonl`) and per episode counts | supplied (max of MOS and rotor, 8 motors) |
| temperature limits | the station file's `motor_temp_warn_c` / `motor_temp_stop_c` apply only to bodies `makers`, `metal`, `so101` (`config.MOTOR_TEMP_BODIES`); a custom driver is not covered | our own `TEMP_WARN_C 60`, `TEMP_STOP_C 70`, `TEMP_RESUME_C 65` in `Arm._monitor`, reported through `alarm()`, which Dream's loop turns into `SafetyStop` |
| `gripper_effort` | `GripperForceCap` (default `grip_force_cap` 0.65, i2rt `gripper_eff` units, not newtons) | **not supplied**: the cap is inactive for this driver |
| motor torque | `damiao.MotorState.torque_nm` is decoded but unused by us | available if we choose to report it |
Our own gripper protection is the stall alarm (leads its angle by more than 4 deg for 2 s: relaxed to where it is) and the 20 deg per write step clamp. Dream's `max_gripper_step` (0.05 per tick, loop side) is separate and stays in force.

## Do our changes work in the predefined station?
Test through Dream's own wrapper (`followers.FollowerArm` around our `Arm` on the fake bus): read carries temps and no effort; write, hold and disengage work; a 75 C motor produces `arm 'left': ... 75 C` from `alarm()`; `close_for_reopen()` switches the motors off, closes the bus and the arm then reads dead; `ReadOnlyArm` reads and refuses writes. All pass.
Not covered by the fake bus: timing of the real station (the 60 s stop wait, handled by the 45 s path limit and preflight in log-026) and the real motors.
The gripper step clamp, the park path and the mapping record are all inside our driver, below Dream's wrapper, so Dream cannot bypass them; the guard reads `~/.dreamlabs/zones.yaml`.

## Gaps and recommendations (nothing applied)
1. `gripper_effort`: Dream's grip force cap only works with i2rt's `gripper_eff` units. `torque_nm` of the DM4310 is in N.m, so the 0.65 number would not transfer. Either leave it off (current state, our stall alarm covers a squeeze) or calibrate on a real grasp first. Recommendation: leave off for now, set `grip_force_cap: 0` explicitly in the station file so the intent is visible.
2. `is_alive()` / `why_stopped()`: not implemented, so the base class answers True. A silent motor shows up as an `ArmError` on read, which ends the run, but the station will not show the "arm stopped answering" Reset prompt. Recommendation: return False and a reason after a read failure or when the control thread dies (offline-testable).
3. Station file keys `motor_temp_*` do nothing for us; keep the limits in the driver (the documented thresholds are 60/70/65 C).
4. `home_before_motors_off` defaults to False and `home_on_key_refused` to True; set the first deliberately once the user decides whether Stop should move the arm home (it adds a move before the 60 s stop wait).

## Unresolved
Motor-side timeout register (not changed), post-stop "motors off" check, left taught path 1.8 cm short of clearance, no live run until the user says so.

## Addendum — is_alive and why_stopped added (user approved)
`Arm.is_alive()` is False when the control thread died (the existing `thread` alarm) or the motors have been silent for over 0.5 s under a running thread; `why_stopped()` gives the text (empty when alive, as Dream's base class does). The station can now show "arm stopped answering" and offer Reset. A dead arm is closed by `close_for_reopen()` without a switch-off (it holds under power, so support it). Tests in `test_followerarm.py`; driver suite 121 passed. Fake bus only; not run on the real arms.
