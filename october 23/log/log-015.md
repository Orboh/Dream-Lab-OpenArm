## Stop-at-boundary guard (built after the restart; not in force until the station is restarted)
- Why: runs 2-4 died with `ArmError: safety zone ... outside the allowed region` because the guard refused the whole pose and the station ends a run on an ArmError.
- `openarm_guard.Guard.limit(prev, q)`: a target that breaks a zone is cut back along the straight joint-space line from `prev` to the last allowed point (16 halvings); an allowed target passes unchanged; stale or missing zones still raise; an arm that is ALREADY outside still raises (it never gets a target further out); guard off = pass-through. `check()` is unchanged.
- `Arm.write` uses it (`Arm._limited`): reference = the last target sent in the last 0.5 s, else the measured pose; one warning per stretch at the edge ("stopped at the edge of the allowed space"); the arm holds at the edge while Dream keeps asking for a point beyond it, the run goes on. Dream is not told: it sees an arm that does not reach its target.
- Tests first: 9 new (guard-level edge, hold, already-outside, stale/missing, off; Arm.write cut, whole, refused-from-outside). Driver 91 passed, workspace 146 passed.
- Offline check on the applied zones (no hardware): from home a 25 deg joint move is cut where the hand reaches the wall, e.g. left joint 1 +25 -> 16.4 deg (hand 11 cm back, 4 cm up), right joint 1 -25 -> 18.7 deg; joint 2 toward the inner wall (the one home touches) stops after about 1 deg.
- Limits: it stops at the edge, it does not slide along the wall or re-plan around it; a task needing a point beyond the edge cannot finish. Inner-wall room is still about 1 cm.

## Why both arms move when one arm is asked for (checked in the station code and log, 17:45) and the two driver changes
- Findings: Dream has no per-arm setting; the model returns an action for BOTH arms every tick and the station sends both (`robots/control.py` builds `Action(left, right)`). Our one-arm lock (`arms.py right|left`, file `~/.dreamlabs/active_arms.json`) was never set (file absent = both active), so nothing held the idle arm. Separately, every Reset acts on both arms: the log shows, for each failed right-arm run, the left arm parking (12-13 s), being raised again (about 12 s) and `home: moving ['left', 'right'] home` (3 full cycles in 2 minutes). Not provable from the inference log: whether the model also asks the idle arm to drift (it does not store actions).
- Change 1: an arm that the lock does not allow is no longer raised to ready when the station opens it (`openarm_v2.Arm.__init__`): it stays at rest, so a Reset does not park and raise it again. Set the lock BEFORE starting the station (`python arms.py right`); if it is set while the other arm is raised, that arm parks once at the next Reset and then stays down. Test: `test_a_locked_arm_is_not_raised_to_ready_when_the_station_opens_it`.
- Change 2: `openarm_motion.RequestTally` + `Arm._note_request`: the log shows what Dream asks of each arm, run by run ("arm left: Dream asks: 12 deg from where this run began (joint 3), 30 deg of joint travel in all; this arm is LOCKED, so it holds still"): first when a run passes 5 deg net, then every 2 s, plus a line when the run ends (3 s of silence). It counts requests, also for a locked arm, so it shows whether an idle arm is asked to move. Tests: 2 pure tally tests, 2 arm log tests. Driver 99 passed.
