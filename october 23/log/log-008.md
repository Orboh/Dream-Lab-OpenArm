# Log 008 — Driver accepts `left` / `right` as addresses (2026-10-23)

## Why
Options for the wizard's merged-adapter problem (log-007) were listed; the user chose the small driver change first, for both arms.
This does not fix the scan merging by itself: it makes the typed-address route easier (type `left` and `right`).

## Change (october 23/driver/openarm_v2.py)
- `LINK_ALIASES = {"left": "can_fol_l", "right": "can_fol_r"}` and `resolve_channel()`: the config's `can_channel`
  `left` / `right` (any case, spaces ignored) opens the real link; any other value is used as written.
- `side_of()` uses the resolved name, so a typed `left` / `right` also tells the side while the wizard passes the address as the side.
- Tests (written first and seen failing, 4 failed): aliases open the right link and side, a link name still works, an unknown address
  is refused. Now 23 tests pass (fake bus).
- Real check, read-only: `ReadOnlyArm` with `can_channel="left"` read the left follower on `can_fol_l`. The right was not queried
  because the wizard is polling it.
- The wizard re-executes the driver file each time it opens an arm, so a restart should not be needed; if it still behaves as before,
  re-select the driver file.
