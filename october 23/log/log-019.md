# Log 019 — Stage 2 follow-up: the joint-5 mapping prepared offline, NOT enabled (2026-10-24)

## Goal
Prepare, offline and with tests, the mapping that makes Dream's `openarm2_faas` model agree with the official OpenArm v10 URDF (log-018: identity mapping leaves a 16.6 cm average hand gap, a joint-5 quarter turn removes it).
No arm moved, no motor frame sent, `~/.dreamlabs/station.yaml`, zones in force and the running station untouched. **Default stays `identity`: behaviour is exactly as before until the user sets `OPENARM_MODEL_MAPPING=official`.**

## What changed (code)
- **New `driver/openarm_mapping.py`**: tables `identity` (default) and `official`; `to_model`, `to_logical`, `outside_model_limits`; chosen by the environment variable `OPENARM_MODEL_MAPPING`.
  `official`: left joint 5 +90 deg, right joint 5 -90 deg, joints 6 and 7 reversed on both arms (an exact solution from `stage2.py mapping`; the form whose start poses stay inside Dream's joint limits).
- **`driver/openarm_v2.py`**: the four places that used the global identity arrays (read positions and velocities, home, write targets, the guard's previous pose) now use the arm's own mapping (`self._sign`, `self._zero`).
- **`driver/openarm_zones.py`**: `ArmKinematics(side, logical=True)` maps logical angles to Dream's model before the forward kinematics. The driver's guard keeps `logical=False` (it already gets Dream's angles).
- **Workspace tools** (`editor`, `designer`, `teach`, `viewer`, `layout`, `outputs`, `zonebuild`, `workspace`) build their kinematics with `logical=True` (they hold the real arm's angles, saved poses and the bundle). `open_sources` returns logical angles.
- **Station file**: `zonebuild.station_fragment` writes the bundle's `home` as Dream's model angles. **`preflight`** compares the station home with the bundle home in the same angles. **`camerapose`** compares the station home with the arm's logical pose after converting.
All of these are no-ops under `identity`.

## Tests
New: `driver/test_openarm_mapping.py` (8), `workspace/test_mapping_workspace.py` (4), one in `workspace/test_preflight.py`. Totals: driver 107, workspace 205, all pass with the default mapping.
They show: exact round trip; read/write/home through a fake CAN bus under `official`; Dream's model with `official` stays within 1 cm of the official URDF over random poses while `identity` is over 10 cm off; the station home and the preflight check use the same angles; the camera-view move still works.
**Stress run with `OPENARM_MODEL_MAPPING=official` set for the whole existing suites:** the preflight tests failed until `preflight.py` was fixed (a real gap, now fixed and tested). 13 workspace tests and 1 driver test still fail only because they hard-code numbers computed under identity (expected hand positions of poses, region boxes, a station home equal to the bundle home, a guard zone test, three camera-pose fakes). They are not code defects; if `official` is adopted they need their expected numbers recomputed.

## The limit this does not remove (important)
Dream's joint 5 range is +-90 deg centred on Dream's own zero. A quarter-turn offset means only half of the arm's joint 5 range lies inside it (left: logical -90..0, right: logical 0..+90), and logical zero sits exactly on the model's limit.
Checked with `outside_model_limits` for the poses in use: every start pose (v2, v5, wood-l1, both arms) and the right rest pose are inside; **the left rest pose (J5 +2.1 deg) maps to 92.1 deg, 2.1 deg outside Dream's limit**; any left twist toward positive J5 is outside, and so is a right twist toward negative.
Unknown: what Dream does with a joint outside its range (clip, refuse, or ignore). That decides whether the left rest pose at station start is a problem. It can be fixed by re-teaching the left rest pose with J5 at or below 0.

## Existing data is not compatible
Zones, reach cells, the table box and the station home captured or written under `identity` were computed with the hand 20+ cm off in bent poses. After switching to `official` they must be **recaptured and reapplied** (Stages 3 and 4). Do not mix: the station file and the zones in force must be written under the same mapping (preflight now checks the home only).

## How to enable later (not done), with gates
1. Set `OPENARM_MODEL_MAPPING=official` in the shell that runs `workspace.py` and in the environment of `dreamcli robot up` (the driver reads it when an arm opens).
2. Recapture the table and allowed area, then `workspace.py apply` (writes the home in model angles) and `preflight`.
3. Offline check on the real station with the arms limp (read-only): Dream's reported hand pose vs a tape measurement at two poses.
4. First live run: the arm user-supervised, one slow short move, hand on the stop; compare "5 cm up" against what the arm does. Stop on any surprise; set the variable back to `identity` to roll back (files from step 2 must be restored from their backups).
Rollback: unset the variable and restore `station.yaml` and `zones.yaml` from the backups `apply` keeps.
