## Reading against Dream's documented inputs
- Dream's docs name the roles `overhead` (over the workspace), `wrist_l`, `wrist_r`, trained on YAM arms. Our head view is a side view at table height.
- For one-arm use the docs say: run it as the right arm, send the left as a fixed parked pose with grip 1 and a **black** `video.wrist_l`, and name only the right arm in the prompt. Our station sends the real left wrist picture of the robot's own body.
- No camera calibration is an input; only views and roles. So the question is the viewpoint, not a calibration file.

## Pass or fail
No hardware fault in the cameras. Two mismatches with Dream's expected inputs found (head is not overhead; left wrist shows the robot, not a black frame). Not proven to be the reason picks fail.
