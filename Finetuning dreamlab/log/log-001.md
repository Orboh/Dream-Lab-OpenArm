## 2. What Dream needs and how the pipeline meets it
| Dream's rule | Our recordings (LeRobot 0.5.2) | The pipeline |
|---|---|---|
| LeRobot **v2.1**, one file per episode | v3.0, all episodes in one file | `convert.py` splits the data and the video per episode and writes `episodes.jsonl` and `tasks.jsonl` |
| The body `koutaueda/openarm2-faas`: state 36, action 34 | 16 values, logical degrees, right then left | `convert.py` maps each value (see below) |
| Joints in radians of Dream's model | logical degrees | the driver's `openarm_mapping` (`official`): J5 ∓90°, J6 and J7 reversed (the station's `OPENARM_MODEL_MAPPING=official`) |
| `_grip` 0 closed to 1 open; `_gripper` jaw drive (left 0..+0.785, right 0..-0.785 rad) | gripper degrees (0 to about -65) | the station's `gripper_closed_deg` and `gripper_open_deg`, clipped like the driver's `read()` |
| `_eef_xyz`, `_eef_rot6`: the tool point in each arm's base frame; rot6 = first two columns | none | Dream's own FK (`dream_ik.solver.ChunkIK("openarm2_faas", "tcp").fk`), the same code the station runs |
| Cameras `head_left`, `wrist_left`, `wrist_right` | `chest`, `wrist_left`, `wrist_right` | `chest` → `head_left` (the same RealSense, 344422070898) |
| H.264/HEVC/AV1/VP9, frames matching the parquet | AV1, one file for all episodes | each episode cut frame for frame and written as H.264 |
| fps 30/15/10/5 | 30 | new recordings at **15** (user decision) |

**Units checked in code:** LeRobot's Damiao bus (`motors/damiao/damiao.py:661`) reads `native - homing_offset` from `follower_<side>.json`, the same file and formula as the driver's `_logical()`. So the recorded degrees are the driver's logical degrees.

## 5. Recording plan (wood block, new recordings)
**Before the first session:**
1. Fix the head (chest) camera for good, looking down on the table, so the block, the box and both grippers are visible. It must not move again: the Live View must see the same view.
2. Station down (`dreamcli robot down`), teleop stopped, the website stopped (it holds the cameras).
3. `bash pipeline.sh prepare` (again whenever the station's home changes).

**Each session** (50 episodes; the user at the e-stop; stop with esc):
- `bash pipeline.sh record`. Every episode starts at the station's home (the recorder aligns to it).
- The prompt is fixed: "Pick up the wood and place it in the box". The Live View must use exactly these words.
- Vary the block's place a little (about ±5 cm) around one marked spot, with the box in one place and the same lighting.
- Move slowly and smoothly: Dream learns the speed it is shown. End each episode still for about 1 s.
- Re-record a failed episode instead of keeping it.

**After each session:**
1. `bash pipeline.sh convert`.
2. `bash pipeline.sh validate`.
3. Check `meta/source.json` for short episodes.

**At 50 episodes:**
1. `upload <name> --yes`.
2. `status` until `processed`.
3. `finetune koutaueda/<name> wood-v1 --yes`.
4. `job` until the checkpoint is set.
5. Choose it in the Live View with the guard on.
